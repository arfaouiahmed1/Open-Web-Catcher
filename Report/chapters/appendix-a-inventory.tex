\section{Material that can be inserted to increase report depth}

To move the report comfortably beyond 100 pages while keeping it natural and technically valuable, the following additions are recommended:

\begin{itemize}
  \item screenshots of the operator console pages;
  \item screenshots of representative landing, hosting, and embedded pages;
  \item exported run traces for one successful and one failed case;
  \item tables of token usage and cost for representative URLs;
  \item a short appendix on API route families and their purpose;
  \item one or two annotated case studies from real target websites.
\end{itemize}

\section{Case-study template for representative target websites}

For each representative website included in the final submission, the following structure can be reused:

\begin{enumerate}
  \item present the starting URL and explain why the page is representative;
  \item show the initial rendered page or landing layout;
  \item state the classification result and the evidence behind it;
  \item summarize the tool sequence used by the selected agent;
  \item present the final extracted hosting links, streams, screenshots, or failure mode;
  \item explain what the case teaches about the strengths or limits of the platform.
\end{enumerate}

This type of structured case study is one of the most efficient ways to increase the final report length while also improving its academic quality.
